## 腾讯文档

依据官方[发起授权](https://docs.qq.com/open/document/app/oauth2/authorize.html)和[获取 Token](https://docs.qq.com/open/document/app/oauth2/access_token.html)文档：

- 需要已注册第三方应用的 client_id。
- 授权 redirect_uri 必须是 HTTPS，并且域名在应用白名单中，不能直接套用桌面 localhost HTTP 回调。
- 授权页使用 new_login=1、scope=all、response_type=code；state 应校验，不能省略防重放机制。
- code 只能用一次；官方要求 Client Secret 与令牌交换由第三方服务端发起，不能把共享 Secret 发到插件包。

因此本轮不发布不可用的腾讯文档占位插件。后续先注册应用和配置 HTTPS 回调服务，再在插件中实现 OAuth 适配、令牌刷新和 API。若增加托管 OAuth 代理，应抽象为跨厂商机制；凭据生命周期由厂商响应驱动，不向宿主添加腾讯专用超时。

## 国内邮箱

`scripts/verify-domestic-access.mjs` 仅探测 TLS 993 与 IMAP CAPABILITY，未使用凭据、未读邮件。QQ、163、126、腾讯企业邮箱均完成证书校验并返回能力列表，详见 `domestic-access.json`。邮箱账户仍需用户在服务端开启 IMAP，并按服务商要求使用客户端授权码；协议开放不代表当前账号已获准访问。QQ 的 XOAUTH2 能力广告也不代表第三方应用可免注册获得 OAuth。

产品建议：单个通用邮箱插件，默认选服务商、填邮箱与授权码，自动推导地址；自定义主机藏在高级选项。先验证 IMAP 再标记连接成功；发送需要单独验证 SMTP，本轮未探测 SMTP、更未测试发送。QQ 邮箱公开帮助入口：[腾讯官方帮助](https://service.mail.qq.com/)。网易公开入口：[163 邮箱](https://mail.163.com/)。企业策略、授权码申请和实际账号读取待后续验收，不能标为已完成生产接入。
